# Подготовка к защите — Strategy Pattern

**Проект:** City Route Planner  
**Студент:** Begaliev Bakdaulet

## Что сказать за 40–60 секунд

«Мой проект рассчитывает примерное время и стоимость поездки тремя способами: пешком, на велосипеде и на машине. В каждом случае алгоритм отличается. Вместо `if/else` я создал общий интерфейс `RouteStrategy` и три его реализации. Класс `Navigator` хранит выбранную стратегию и вызывает её метод `calculate()`. В `Main` я могу менять стратегию через `setStrategy()`, не создавая новый `Navigator`. Это и есть паттерн Strategy».

## Что показать в коде

1. `RouteStrategy.java` — общий интерфейс, метод `calculate(Route route)`.
2. `WalkingStrategy.java`, `BicycleStrategy.java`, `CarStrategy.java` — три разных алгоритма.
3. `Navigator.java` — сам **Context**. Поле `private RouteStrategy strategy` и метод `setStrategy()`.
4. `Navigator.planRoute()` — делегирует работу одной строкой: `strategy.calculate(route)`.
5. `Main.java` — **Client**, который создаёт стратегии и меняет их во время работы.
6. `Route.java` — данные о маршруте. `RouteResult.java` — время и стоимость.

## Ответы на возможные вопросы

**Что такое Strategy?** Паттерн, который позволяет менять алгоритм во время работы программы через общий интерфейс.

**Где Strategy в твоём коде?** Интерфейс `RouteStrategy` и классы `WalkingStrategy`, `BicycleStrategy`, `CarStrategy`.

**Где Context?** `Navigator`. Он не знает формулы конкретного транспорта; только вызывает `calculate()`.

**Что делает `setStrategy()`?** Заменяет объект алгоритма, который будет использован при следующем расчёте.

**Зачем это лучше, чем if/else?** Не нужно переписывать `Navigator` каждый раз, когда появляется новый вид транспорта. Каждая формула лежит отдельно.

**Почему условия в `Main` не нарушают Strategy?** В `Main` проверяется ввод пользователя. Нет выбора формулы через `if` или `switch` внутри `Navigator`.

**Как добавить автобус?** Создать `BusStrategy implements RouteStrategy`, реализовать `calculate()`, добавить его в варианты меню в `Main`. `Navigator` менять не нужно.

**Strategy и State — разница?** Strategy выбирает клиент, чтобы заменить алгоритм. State обычно меняется из-за внутреннего состояния объекта и переходов между состояниями.

**Что значат стрелки UML?** Пустой ромб — `Navigator` хранит ссылку на стратегию (aggregation). Пунктир с пустым треугольником — `implements`. Пунктирная стрелка — зависимость (uses).

**Почему не настоящий Google Maps?** Это учебная модель: расстояние известно, а время и стоимость оцениваются по простым формулам. Цель задания — показать Strategy, а не получить реальные маршруты через API.

## Демо на защите

1. В IntelliJ открыть `Main.java`, нажать Run — сразу появятся три расчёта.
2. Чтобы показать ручную смену алгоритма, выбрать Run → Edit Configurations → Program arguments: `--interactive`.
3. Запустить и по очереди ввести `1`, `2`, `3`, затем `0`.
4. Вернуться к `Navigator.java` и показать, что один `setStrategy()` меняет алгоритм без изменений Context.

**Пример для 7.5 км:** пешком — 90 минут / 0 ₸; велосипед — 35 минут / 0 ₸; машина — 20 минут / 888 ₸.
